About Value Identification Standard (VIS)

Architecture: VFM® — Value Flow Mechanisms Architecture Category: Governance & Enforcement Subcategory: Value Lifecycle Governance Parent Standard: Value Identification Standard (VIS) Governed Space: Value Identification

Canonical Definition

Value Identification Standard (VIS) governs how potential or existing manifestations of value are identified, distinguished, bounded, contextualized, and established as governable Value Objects before their origin, existence, state, change, development, degradation, nullification, restoration, or extinction can be determined.

VIS establishes the first methodological control point of the VFM® value lifecycle.

Its foundational question is simple:

What exactly is the value being governed?

Why VIS Matters

Value is frequently discussed without first identifying the precise subject to which the value claim relates.

Organizations may refer to the value of an asset, capability, service, technology, relationship, right, resource, information object, infrastructure, process, opportunity, or future benefit without clearly separating:

the object or source associated with value

from

the value itself.

This creates ambiguity throughout every later stage of the value lifecycle.

Before asking where value originated, whether value exists, how much it has changed, whether it has degraded, whether it has reached zero, or whether it can be restored, the relevant value must first be identifiable as a governable object.

VIS creates that foundation.

Identification Before Valuation

VIS does not determine how much something is worth.

It does not assign a price.

It does not determine market value, accounting value, taxable value, legal value, economic value, or social value.

Its function comes earlier.

VIS establishes:

what value is being referred to, what it is associated with, where its boundaries lie, and which value manifestation is entering governance.

This distinction is fundamental:

Value Identification ≠ Value Measurement

A value cannot be meaningfully measured, classified, tracked, or governed if the subject of the value claim remains ambiguous.

The Value Object

VIS introduces the Value Object as the governable subject through which a particular manifestation of value can be identified and followed across the VFM® lifecycle.

A Value Object may relate to value associated with:

a physical asset; a digital asset; a capability; a service; a process; knowledge or information; intellectual property; infrastructure; a resource; a contractual or economic relationship; access or availability; productive capacity; technological capability; an opportunity; an operational function; another identifiable source or manifestation capable of carrying value.

The Value Object does not itself prove that value exists.

Identification establishes the object of inquiry.

Subsequent VFM® standards determine what happens to value.

Value Object ≠ Asset

Not every Value Object must be an asset.

An asset may contain, support, generate, preserve, lose, or recover multiple forms of value.

Likewise, value may arise from relationships, capabilities, conditions, access, knowledge, coordination, timing, or other phenomena that cannot be adequately described as conventional assets.

VIS therefore prevents VFM® from becoming merely an asset-governance architecture.

VFM® governs value itself.

Value Identification Before Value Origin

Value Identification precedes Value Origin for a methodological reason.

Before asking:

Where did this value originate?

the architecture must know:

Which value are we investigating?

VIS therefore creates the entry point:

Value Identification → Value Origin → Value Emergence → Value Recognition → Value State → Value Change → Value Development / Value Degradation → Value Nullification → Value Restoration / Value Extinction

Identification does not establish origin.

It establishes the governable subject for which origin can subsequently be investigated.

Multiple Values Within One Object

A single object may contain or support multiple distinct Value Objects.

For example, industrial equipment may simultaneously have:

productive value, operational value, resale value, material recovery value, technological value, strategic value, and informational value.

These values may follow different lifecycles.

One may degrade while another increases.

One may reach zero while another remains substantial.

VIS therefore requires value manifestations to be sufficiently distinguished rather than assuming that an object possesses one universal value state.

This capability becomes particularly important when VFM® is applied across complex organizations, public infrastructure, technology, finance, industrial systems, or national economic environments.

Context Matters

Value identification may depend upon context.

The same underlying object may represent different value within different:

purposes; environments; users; systems; time periods; operational conditions; economic contexts; institutional contexts; technological contexts.

VIS therefore does not treat value as automatically universal merely because the underlying object is identifiable.

It requires the relevant value context to be made explicit.

What VIS Does Not Determine

VIS does not determine:

whether the identified value actually exists; where that value originated; whether value has emerged; whether value should be recognized; the amount of value; the current Value State; whether value increased or decreased; whether value has reached zero; whether value can be restored; who owns the underlying object; whether the object is legally recognized; whether a value claim is validated; whether a transaction is taxable; whether the value is ethically desirable.

These questions belong to subsequent VFM® standards or other governance architectures.

This boundary protects VIS from becoming a general valuation, identity, ownership, accounting, taxation, or validation framework.

Use Case 1 — Industrial Asset

A factory owns a machine that is no longer used for its original production function.

A conventional assessment may simply ask:

What is the machine worth?

VIS first separates the possible Value Objects.

The machine may have lost most of its productive value while retaining:

resale value, component value, material value, replacement-part value, technological value, or strategic reserve value.

VFM® can then govern each relevant value lifecycle separately.

The machine therefore does not have to be simplistically classified as either:

valuable

or

worthless.

VIS identifies which value is actually being discussed before its lifecycle is assessed.

Use Case 2 — Digital or Technological Capability

An organization develops a software model that is no longer commercially successful.

Its immediate commercial value may have significantly degraded.

However, the same development may retain:

technical knowledge, training data relationships, reusable components, intellectual capability, research value, integration capability, or future redevelopment potential.

VIS enables these value manifestations to be distinguished before VFM® determines their respective origins, states, changes, degradation, zero-value conditions, restoration possibilities, or extinction.

This prevents the disappearance of one form of value from being incorrectly interpreted as the disappearance of all value associated with the underlying object.

Relationship to Other VFM® Standards

VIS establishes the Value Object.

The Value Origin Standard determines where the identified value originates.

The Value Emergence Standard determines whether and when value actually comes into existence.

The Value Recognition Standard governs when existing value becomes recognized within the value lifecycle.

The Value State Standard determines the current governed state of value.

Subsequent VFM® standards govern change, development, degradation, nullification, restoration, and extinction.

VIS therefore provides the identification layer upon which the complete VFM® lifecycle depends.

Relationship to Other OOF® Architectures

VIS identifies the value being governed but does not absorb responsibilities belonging to other architectures.

OBIDENITY® may govern identity, origin-bound identity, ownership, authority, provenance, transfer, and continuity of the underlying entity.

CLA™ may govern formal classification.

VALIDOS® may govern whether relevant claims or determinations have been sufficiently validated.

INTEGROS® may govern integrity.

ADIT® may govern audit and evidence.

GOA™ may govern governance authority and structure.

VFM® remains concerned with the independent question:

What is happening to value?

Enterprise Value

VIS provides organizations with a repeatable method for identifying value before attempting to measure, manage, account for, preserve, develop, recover, tax, exchange, or govern it.

This can expose value that conventional object-level assessments may overlook.

It can also prevent fundamentally different forms of value from being combined into one ambiguous valuation.

The result is a clearer foundation for downstream value governance and for interfaces with accounting, economic, investment, taxation, asset-management, public-policy, and decision systems.

Foundational Principle

Before value can be governed, the value being governed must be identifiable.

An object may contain many forms of value.

A value may exist in many contexts.

A change in one value does not necessarily represent a change in another.

VIS therefore establishes identification before origin, emergence, state, change, or valuation.

Canonical Closing Statement

Value Identification Standard establishes the entry point of VFM® — Value Flow Mechanisms Architecture by defining how potential or existing manifestations of value become identifiable, distinguishable, bounded, contextualized, and governable Value Objects. By separating the identification of value from the identification of the underlying asset, from value measurement, ownership, classification, validation, accounting, taxation, and market pricing, VIS creates the methodological foundation required to follow value independently throughout its complete lifecycle. VFM® can govern where value originates, when it emerges, how it changes, how it develops or degrades, when it reaches zero, whether it can be restored, and when it becomes extinct only after the value being governed has first been made explicit.
