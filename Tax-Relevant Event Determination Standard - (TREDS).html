Canonical Definition

The Tax-Relevant Event Determination Standard (TREDS) governs how
an event that has passed through the preceding TREGA™ governance
layers is formally evaluated and determined to constitute a
sufficiently governed Tax-Relevant Event for downstream record
governance and jurisdiction-specific taxation analysis.

TREDS establishes whether the governed Event structure is
sufficiently complete, coherent, attributable, bounded,
temporally and spatially situated, participatory,
value-associated, relationship-aware, and methodologically
reliable to become a formal Tax-Relevant Event within TREGA™.

Its principal transition is:

Governed Event Relationship Structure

↓

Tax-Relevant Event Determination

↓

Determined Tax-Relevant Event

TREDS does not determine whether tax is legally due.

It does not determine the applicable jurisdiction, taxpayer, tax
base, tax rate, exemption, deduction, tax point, filing
obligation, or legal tax consequence.

Its foundational distinction is:

Event Determination ≠ Taxability Determination.

Purpose

The purpose of TREDS is to create a formal governance threshold
between:

an event that has been progressively structured by TREGA™

and:

an event that is sufficiently governed to be treated as
Tax-Relevant for downstream taxation analysis.

Without this threshold, downstream systems may consume:
incomplete events; unresolved events; contradictory events;
technically generated records; improperly bounded activities;
uncertain participant structures; unresolved Value Associations;
or unstable Event Relationships

as though they were fully governed taxation inputs.

TREDS prevents that failure.

It establishes a formal determination layer before the event
becomes a governed tax-relevant record.

Core Question

Has the event been governed sufficiently across the TREGA™
lifecycle to become a formal Tax-Relevant Event suitable for
downstream jurisdiction-specific taxation analysis without
determining the tax itself?

Tax-Relevant Event Determination

Tax-Relevant Event Determination is the formal TREGA™ governance
decision that an event has been sufficiently governed to proceed
as a Tax-Relevant Event.

It answers:

Is this event sufficiently governed for taxation systems to
evaluate it?

It does not answer:

Is this event legally taxable?

That distinction is fundamental.

Tax-Relevant Event ≠ Legally Taxable Event.

Determination Readiness

An event shall not enter formal Determination merely because it
exists in an operational system.

TREDS shall first establish whether the event is ready for
determination.

Readiness may require that all materially necessary upstream
governance areas are sufficiently established.

These include, where applicable: Context; Recognition; Formation;
Boundary; Timing; Location; Participation; Value Association;
Event Relationships.

Event Presence ≠ Determination Readiness.

Readiness Completeness

Determination readiness requires sufficient completeness for the
specific event.

This does not require infinite or total information.

It requires sufficient governed information to support a
defensible determination.

Determination Completeness ≠ Total Data Capture.

Missing immaterial information shall not automatically block
determination.

Missing materially necessary information shall.

Readiness Coherence

Upstream governance outputs shall be sufficiently coherent.

For example: Event Boundary should not contradict Formation;
Timing should not contradict the governed Event structure;
Participant structure should fit the Event; Value Association
should refer to the governed Event; Event Relationships should
not conflict with Event Identity.

Material contradictions may prevent determination.

Data Availability ≠ Governance Coherence.

Readiness Stability

The event should be sufficiently stable to support formal
determination.

A structure undergoing unresolved Formation, Boundary,
Participation, Value, or Relationship reconsideration may not yet
be ready.

However, perfect permanence is not required.

Governance Stability ≠ Immutability.

Determination Conditions

TREDS shall govern the conditions that must be satisfied before a
Tax-Relevant Event can be formally determined.

Conditions may include: Event Identity sufficiently established;
Event Formation sufficiently governed; Event Boundary
sufficiently governed; Event Timing sufficiently established;
Event Location sufficiently represented where material; Event
Participation sufficiently represented; material Value
Association sufficiently governed; material Event Relationships
sufficiently governed; material conflicts sufficiently resolved
or explicitly qualified; material uncertainty sufficiently
controlled; and sufficient traceability for downstream
reconstruction.

The conditions may vary according to event complexity.

The standard governs sufficiency, not identical data volume for
every event.

Material Sufficiency

TREDS operates on material sufficiency.

The relevant question is not whether every possible data field
exists.

The question is whether the governed Event representation is
sufficient for downstream taxation evaluation without requiring
the tax system to reconstruct Event Reality itself.

More Data ≠ Greater Determination Quality by default.

Event Integrity at Determination

TREDS shall evaluate whether the event remains internally
coherent across its governed layers.

An event should not be formally determined where: Event Identity
is unresolved; Boundary materially conflicts with Formation;
Value Association materially contradicts Event structure;
Participant structure is fundamentally uncertain; or material
relationships remain incompatible with the event representation.

Determination is therefore a governance synthesis point.

It is not merely another classification label.

Determination Decision

The Determination Decision establishes the formal status of the
governed Event.

Possible decisions include:

Tax-Relevant Event Determined

Determination Conditional

Determination Deferred

Determination Rejected

Determination Uncertain

Determination Conflicted

Determination Reconsideration Required

The decision shall be explicit.

Silence shall not be interpreted as determination.

No Decision ≠ Positive Determination.

Positive Determination

A positive determination means that the event is sufficiently
governed to become a formal Tax-Relevant Event.

It means:

Eligible for downstream jurisdiction-specific taxation analysis.

It does not mean:

Tax legally due.

Therefore:

Positive Event Determination ≠ Positive Tax Determination.

Conditional Determination

An event may be sufficiently governed for downstream processing
while one or more explicitly bounded conditions remain.

Conditional determination may be appropriate where uncertainty is
controlled and does not invalidate the Event structure.

The condition shall remain visible.

Conditional Determination ≠ Unqualified Determination.

Deferred Determination

Determination shall be deferred where materially necessary
upstream governance remains incomplete.

Examples may include unresolved: Event Boundary; Event
Participation; Value Association; Event Relationship; or material
Event Identity questions.

Deferred Determination ≠ Rejected Event.

The event may become determinable after additional governance.

Rejected Determination

TREDS may reject formal Tax-Relevant Event Determination where
the available governed structure does not support the existence
of a sufficiently constituted Tax-Relevant Event.

Rejection may result where: Recognition was incorrect; Formation
fails; Event Boundary cannot be established; the apparent event
is merely a technical artifact; or another fundamental governance
failure exists.

Determination Rejection ≠ Legal Non-Taxability.

It means the event does not currently satisfy TREGA™ requirements
for a governed Tax-Relevant Event.

Determination Uncertainty

Uncertainty does not automatically invalidate an event.

TREDS shall distinguish between: immaterial uncertainty; bounded
uncertainty; material uncertainty; unresolved uncertainty.

The effect on determination shall depend on whether the
uncertainty prevents reliable downstream taxation analysis.

Uncertainty ≠ Automatic Determination Failure.

Material Uncertainty

Uncertainty becomes material where it could materially change the
governed identity or structure of the Event.

Examples may include uncertainty over: whether one or several
events exist; which participant materially participated; which
governed Value Result belongs to the event; which Event Boundary
applies; or which relationship structure is valid.

Material uncertainty may require deferral or conditional
determination.

Determination Conflict

Conflicting upstream governance outputs may prevent reliable
determination.

For example: one system represents one event; another represents
two events; one source identifies Participant A; another
identifies Participant B; one Value Association conflicts with
another.

TREDS shall preserve material conflict.

Conflict ≠ Permission to Select the Convenient Result.

Conflict Resolution Boundary

TREDS may evaluate whether a conflict prevents determination.

It does not necessarily resolve the underlying subject matter
itself.

TREDS governs determination impact, not ownership of every

Determination Confidence

TREDS may qualify confidence in the determination where useful.

Possible states may include: High; Qualified; Limited;
Conditional; Ambiguous; Conflicted; Unresolved.

Confidence shall not replace the determination decision.

Confidence Score ≠ Determination Decision.

Determination Reasoning

A formal Determination shall be supported by reconstructable
governance reasoning.

The reasoning should show: which event is being determined; which
upstream governed outputs were relied upon; what material
conditions were satisfied; what uncertainties remained; whether
conflicts existed; and why the resulting determination state was
reached.

Determination Result Without Governance Basis ≠ Governed
Determination.

Determination Traceability

The determination shall remain traceable to its upstream
governance lineage.

This allows downstream systems to understand not only that a
Tax-Relevant Event exists, but how that conclusion was reached.

Traceability supports: review; audit; correction;
reconsideration; cross-system interoperability; and
multi-jurisdiction evaluation.

TREDS does not replace TREGS Event Record Governance.

It establishes the determination information that TREGS will
formally structure into the governed Event Record.

Event Determination and Recognition

Recognition identifies that an occurrence may require TREGA™
governance.

Determination decides whether the fully governed Event is ready
to become a Tax-Relevant Event.

Therefore:

Event Recognition ≠ Event Determination.

TRERS is the entry recognition layer.

TREDS is the formal downstream determination layer.

Event Determination and Formation

Formation establishes what constitutes the event.

Determination evaluates whether that formed and subsequently
governed event is sufficiently complete.

Event Formation ≠ Event Determination.

TREDS cannot compensate for defective Formation by declaring the
event determined.

Event Determination and Boundary

Boundary establishes where the event begins and ends
conceptually.

TREDS consumes that result.

Event Determination ≠ Event Boundary Determination.

Event Determination and Timing

TREDS does not determine Event Time.

It evaluates whether the governed timing information is
sufficient where timing is material.

Event Determination ≠ Event Timing Determination.

and:

Event Determination ≠ Legal Tax Point Determination.

Event Determination and Location

TREDS may require sufficient Event Location information where
material.

However:

Event Determination ≠ Tax Jurisdiction Determination.

Event Location remains operationally governed by TRELS.

Jurisdictional tax nexus remains downstream.

Event Determination and Participation

TREDS consumes the governed participation structure.

It does not determine taxpayer status.

Event Participant ≠ Taxpayer.

and:

Event Determination ≠ Taxpayer Determination.

Event Determination and Value

TREDS may require sufficient Value Association where materially
relevant.

It does not determine taxable value.

Governed Value Association ≠ Taxable Value.

and:

Event Determination ≠ Tax Base Determination.

Event Determination and Event
Relationships

TREDS consumes the Governed Event Relationship Structure from
TRERLS.

It evaluates whether relationship ambiguity or structural
conflict prevents determination.

It does not recreate the Event Relationship structure.

Event Determination ≠ Event Relationship Redetermination.

Determination of Independent Events

Several strongly related events may each receive independent
Tax-Relevant Event Determination.

Relationship strength does not eliminate Event Identity.

Related Events ≠ One Determined Event by default.

Determination of Event Groups

Events belonging to one Event Group may still require individual
Event Determination where they retain separate Event Identities.

Event Group ≠ Determination Unit by default.

The governed Event Identity remains primary.

Determination after Merge

Where ERLMM establishes a governed Merge and Formation/Boundary
governance support the resulting event, TREDS shall determine the
resulting governed Event representation.

Prior Event representations remain traceable.

Merged Representation ≠ Historical Erasure.

Determination after Split

Where an event has been legitimately split, each resulting
independently governed Event may require separate Determination.

Split Result ≠ Automatic Positive Determination.

Each resulting event must satisfy applicable TREDS conditions.

Determination and Technical Records

A technical record, transaction record, log entry, blockchain
transaction, API call, database object, invoice line, or
accounting entry is not automatically a determined Tax-Relevant
Event.

Technical Record ≠ Determined Tax-Relevant Event.

TREDS evaluates the governed Event, not the technical artifact.

Determination and Payments

A payment may constitute an independently governed event, form
part of another Event structure, or relate to several events.

TREDS does not assume:

Payment = Tax-Relevant Event

without preceding TREGA™ governance.

Determination and Invoices

An invoice may provide evidence or operational structure.

It does not itself establish Event Determination.

Invoice ≠ Tax-Relevant Event by default.

Determination and Contracts

A contract may contextualize one or many events.

It does not itself establish a determined event.

Contract ≠ Tax-Relevant Event by default.

Determination and Blockchain Transactions

A blockchain transaction may correspond to: one event; part of
one event; several event relationships; or a purely technical
operation.

Therefore:

Blockchain Transaction ≠ Determined Tax-Relevant Event by
default.

TREDS relies on the complete governed Event structure.

Determination and Smart Contracts

Smart-contract execution does not automatically create one
Tax-Relevant Event per call or transaction.

Smart-Contract Execution ≠ Tax-Relevant Event Determination.

Determination and AI Agents

AI agents may initiate or execute large numbers of activities.

TREDS determines governed Tax-Relevant Events rather than
counting Agent Actions.

Agent Action ≠ Tax-Relevant Event by default.

Determination and Machine Activity

Machines may generate millions of technical operations.

Only those operational structures that pass TREGA™ governance may
become determined Tax-Relevant Events.

Machine Operation Count ≠ Tax-Relevant Event Count.

Determination and Automation

Automated classification or detection systems may propose a
determination.

They shall not substitute for the governance conditions of TREDS.

Automated Classification ≠ Governed Event Determination.

Determination and AI Confidence Scores

AI systems may assign confidence or probability to a candidate
Event.

Such scores may inform governance.

They do not constitute the Determination itself.

Model Confidence ≠ Governance Determination.

Cross-System Determination

One event may be represented across several systems.

TREDS shall determine the governed Event representation rather
than treating each system record as a separate Event.

System Record Count ≠ Event Count.

Cross-Organization Determination

The same broader Event may involve several organizations.

TREDS may consume governed cross-organizational information
without deciding ownership, accountability, or tax liability.

Multiple Organizations ≠ Multiple Events by default.

Cross-Border Determination

An event may span several physical or digital locations.

TREDS may still determine the event as Tax-Relevant without
deciding which jurisdiction may tax it.

Cross-Border Tax-Relevant Event ≠ Tax Jurisdiction Determination.

Multi-Jurisdiction Readiness

A central purpose of TREDS is to produce an event representation
that can support more than one legitimate downstream
jurisdictional evaluation.

The canonical model is:

One Determined Tax-Relevant Event

↓

Multiple Jurisdictional Tax Evaluations

TREDS therefore seeks to preserve the governed Event Reality
independently of later legal interpretation.

Jurisdiction-Neutral Determination

Determination conditions shall not be rewritten merely to fit one
jurisdiction's tax law where the event is intended for
jurisdiction-neutral TREGA™ governance.

Legal rules may later consume the event differently.

TREGA™ does not permit downstream law to retroactively redefine
Event Reality.

Jurisdictional Interpretation ≠ Event Determination Authority.
Tax-Relevant ≠ Taxable

This is the central boundary of TREDS.

An event becomes Tax-Relevant when it is sufficiently governed
for taxation analysis.

It becomes legally taxable only if the applicable jurisdictional
rules establish that legal consequence.

The architecture therefore preserves:

Tax-Relevant Event

↓

Jurisdictional Tax Evaluation

↓

Legal Tax Determination

not:

Tax-Relevant Event = Taxable Event
Taxability Boundary

TREDS shall never determine: whether a supply is taxable; whether
income is taxable; whether a transfer is taxable; whether VAT is
due; whether withholding applies; whether capital gains arise;
whether an exemption applies; or whether any other legal tax
consequence exists.

These belong downstream.

Tax Jurisdiction Boundary

TREDS may determine that Location governance is sufficient for
downstream evaluation.

It does not select the taxing jurisdiction.

Jurisdiction-Ready ≠ Jurisdiction-Determined.

Taxpayer Boundary

TREDS may consume governed Event Participation.

It does not determine which participant is legally the taxpayer.

Participant ≠ Taxpayer.

Tax Base Boundary

TREDS may require that material Event–Value relationships are
governed.

It does not convert governed value into legal Tax Base.

Value Association ≠ Tax Base.

Tax Rate Boundary

No TREDS Determination contains a tax rate.

Determined Tax-Relevant Event ≠ Tax Rate Determination.

Tax Period Boundary

Event Timing may be available.

TREDS does not translate operational timing into a
jurisdiction-specific taxable period.

Operational Event Time ≠ Legal Tax Period.

Legal Characterization Boundary

Tax law may later characterize the event as: sale; service;
transfer; income; disposal; import; export; remuneration;
royalty; taxable benefit; or another legal category.

TREDS does not make that legal characterization unless such
terminology merely reflects an upstream governed operational
description.

Governed Event Determination ≠ Legal Tax Characterization.

Determination Readiness Across Different
Event Types

TREDS shall remain adaptable to different Event structures.

A simple event may require relatively little information.

A distributed autonomous transaction may require significantly
more governance.

A multi-party cross-border event may require stronger Location,
Participation, Value, and Relationship representation.

The determination threshold shall therefore be materially
sufficient, not mechanically identical.

Determination governance should be proportionate to: Event
complexity; Event materiality; number of participants;

Determination Reconsideration

A prior Event Determination may require reconsideration where
materially relevant governance changes.

Examples include: corrected Event Boundary; corrected
Participant; revised Value Association; newly discovered Event
Relationship; Merge or Split; newly available operational
information; or correction of material upstream error.

TREDS shall preserve both the prior and reconsidered

Reconsideration ≠ Historical Erasure.

Determination Supersession

A new Determination may supersede an earlier one.

Supersession shall not erase the historical record.

Superseded Determination ≠ Deleted Determination.

Determination Correction

Where a determination contains an error that does not require
complete reconsideration of Event structure, a governed
correction may be issued.

Correction shall remain traceable.

Correction ≠ Silent Replacement.

Determination Finality

TREDS may establish operational finality sufficient for
downstream use.

This does not imply absolute legal finality.

Future corrections, evidence, or upstream governance changes may
justify reconsideration.

Governance Finality ≠ Legal Finality.

Determination Interoperability

A Determined Tax-Relevant Event should be representable across
systems without losing its core governance meaning.

Interoperability requires preservation of: Event identity;

uncertainty; conflicts; and determination lineage.

Formal record structure belongs to TREGS.

Determination Auditability

The relevant reviewer should be able to establish: what event was
determined; on what governed basis; what conditions were
satisfied; what uncertainty remained; who or what governance
process produced the result; and whether the determination was
later corrected or reconsidered.

ADIT® may govern broader audit and evidential requirements.

Determination Validation Boundary

Determination Integrity Boundary

Determination Accountability Boundary

Governance Logic

IF the governed Event has not completed materially necessary
upstream TREGA™ governance, THEN formal Tax-Relevant Event
Determination shall not occur.

IF materially necessary Event Context, Formation, Boundary,
Timing, Location, Participation, Value Association, or Event
Relationship governance remains unresolved, THEN Determination
shall be deferred, conditioned, or otherwise qualified according
to material impact.

IF the governed Event structure is sufficiently complete,
coherent, stable, and reconstructable for downstream taxation
analysis, THEN a positive Tax-Relevant Event Determination may be
issued.

IF uncertainty remains but does not materially undermine Event
Identity or downstream interpretability, THEN Conditional or
Qualified Determination may be permitted.

IF material uncertainty prevents reliable Event interpretation,
THEN Determination shall remain deferred, uncertain, or
unresolved.

IF upstream governance outputs materially conflict, THEN the
conflict shall remain visible and the authoritative upstream
layer shall be invoked where required.

IF the apparent Event is only a technical artifact and does not
satisfy Event Formation or Boundary governance, THEN
Determination shall be rejected.

IF Merge or Split has changed the governed Event structure, THEN
the resulting Event representation shall undergo appropriate
Determination rather than inheriting positive Determination
automatically.

IF an automated system proposes a determination, THEN that
proposal shall remain subject to the same TREDS conditions as a
human-generated determination.

IF a positive Determination is established, THEN the resulting
Determined Tax-Relevant Event shall proceed to TREGS for Governed
Event Record construction.

IF later materially relevant information changes the Event
structure, THEN the Determination may be reconsidered without
erasing its prior governance history.

Enterprise Application

TREDS establishes the decision threshold between governed Event
construction and downstream tax infrastructure.

A canonical enterprise path is:

ERP / Commerce / Banking / Marketplace / Blockchain / AI Agent /
Machine System

→ TREGA™ Event Governance

→ Governed Event Relationship Structure

→ TREDS — Tax-Relevant Event Determination

→ Determined Tax-Relevant Event

→ TREGS — Governed Tax-Relevant Event Record

→ TRECLS — Jurisdiction-Ready Event Lifecycle

→ Country / Jurisdiction Tax Engine

→ Legal Tax Determination

This separation allows organizations to construct one governed
Event Reality layer that can be consumed by multiple tax systems
without forcing each tax engine to independently reconstruct what
happened.

Operational Value

TREDS provides a practical control point for organizations
managing complex economic activity.

It prevents: raw system records entering tax engines as if they
were governed events; inconsistent Event representations across
systems; unresolved Event Boundaries entering legal tax
determination; unknown participants being silently treated as
taxpayers; Value Associations being treated automatically as Tax
Base; technical blockchain operations being counted automatically
as taxable events; AI-agent actions becoming tax events merely
because they were machine-generated; and jurisdiction-specific
interpretations from rewriting the underlying Event Reality.

The result is a reusable, jurisdiction-neutral Event
Determination layer.

Canonical Boundary

TREDS owns the governance of Determination Readiness,
Determination Conditions, Determination Sufficiency,
Determination Decision, Determination Uncertainty, Determination
Conflict, Determination Qualification, Determination Reasoning,
Determination Reconsideration, Determination Correction,
Determination Supersession, and the formal establishment of a
Determined Tax-Relevant Event.

TREDS does not own Event Context, Recognition, Formation,
Boundary, Timing, Location, Participation, Value lifecycle, Value
Association, Event Relationship construction, Event Record
structure, Event lifecycle continuity, identity, ownership,
provenance, accountability, liability, tax jurisdiction, taxpayer
status, legal tax point, taxable value, Tax Base, Tax Rate,
exemption, deduction, Tax Liability, reporting obligation,
collection, enforcement, or any other jurisdiction-specific legal
tax consequence.

Its governance begins when the Event Relationship structure and
materially necessary upstream TREGA™ outputs are available for
formal Determination.

Its governance ends when the event has received a sufficiently
governed Determination state for downstream Event Record
Governance under TREGS.

Canonical Closing Statement

TREDS establishes the point at which a governed event becomes
sufficiently complete, coherent, and reconstructable to enter
taxation infrastructure without allowing event governance to
become tax law.

Its purpose is not to decide whether tax is due. Its purpose is
to ensure that when a jurisdiction asks what happened, the event
presented to that jurisdiction has already been methodologically
governed.

Tax-Relevant Event ≠ Legally Taxable Event.

Event Determination ≠ Taxability Determination.

Jurisdiction-Ready ≠ Jurisdiction-Determined.

TREGA™ governs the event. The jurisdiction governs the tax.
